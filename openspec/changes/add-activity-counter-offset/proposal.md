## Why

FSUIPC offset `0x337E` is a 16-bit activity counter: real FSUIPC increments it every time it receives a call or message from the flight simulator, and wraps it at `0xFFFF`. Clients poll it to check that the simulator is alive and that FSUIPC is still being driven. xplane-uipc doesn't serve the offset at all, so those clients see "not in table" and may conclude the sim is stalled or disconnected.

The value can't come from `mappings.toml`. There is no dataref for it, and a static value or expression can't count. It has to be generated by the plugin itself, which makes it the first offset not defined in the mapping file.

## What Changes

- Add a plugin-generated `u16` activity counter at offset `0x337E`. It increments by one each flight loop cycle and wraps from `0xFFFF` to `0`.
- Serve it as read-only. Client writes to `0x337E` take the existing non-writable path.
- Built-in offsets take precedence. A `mappings.toml` entry targeting `0x337E` is ignored, with a warning logged when mappings are resolved.
- The counter survives "Reload Mappings". It only resets when the plugin is restarted.

## Capabilities

### New Capabilities
- `builtin-offsets`: Offsets whose values are generated by the plugin rather than defined in `mappings.toml`, starting with the `0x337E` activity counter.

## Impact

- **`xplane_uipc/src/plugin_state.rs`**: New counter state on `PluginState`, incremented and inserted into the value table in `update()`. User mappings on built-in offsets are dropped.
- **`xplane_uipc/src/lib.rs`**: Warn when a loaded mapping collides with a built-in offset.
- **`ipc_host`**: No changes. The counter is an ordinary `Value::UnsignedInteger16` entry with `writable: false`.
- **Docs**: Mention the built-in offset in the README mapping documentation.
